# HID capture - Phase A (key remap) - FiiO KB1 CM_F1 FW1.2.26

Report ID: **0x21 (33)**, report length 63 (64-byte frame incl. id).
Transport: WebHID output report `device.sendReport(0x21, buf)`.

## Frame header (decoded)
```
byte0      = 0x12            magic / protocol tag (constant)
byte1..2   = checksum16 LE   (sum-based; changes by +N when a payload byte changes by +N)
byte3      = cmd             0x04 = read/enumerate,  0x3c = write KeyInfo,  0x06 = save/commit
byte4+     = payload
```

## Set-key payload (cmd 0x3c), offsets within the 63-byte frame
```
b4  b5   = 00 10
b6       = KEY INDEX   (2, 1, 0 for the three writes)
b7       = 01
b8..b10  = 00 00 00
b11..b12 = addr LE     (04e2 / 0c4e / 13ba  -> per-key config address, +~1900 each)
b13..b18 = 6c 07 08 07 08 07   (geometry/template - copy verbatim)
b19      = 64
b20..b22 = 00 00 00
b23      = 09          KeyData class = keyboard key
b24..b27 = key_val u32 LE   ->  b27 low byte = HID usage code
b28..b30 = 00 00 00
b31      = 03          KeyData mode (normal)
rest     = 00 padding
```

## Checksum verification
Within a pair only b1..b2 (chk) and b27 (keycode) change; chk16 delta == keycode delta
(pair1 +4, pair2 +5, pair3 +6). => chk = 16-bit LE additive sum over payload. Confirm exact
byte range when implementing (sum of bytes[3..] most likely).
